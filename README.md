# ✈️ AI Travel Planner (TripMind)

**Your next adventure, intelligently planned.**

AI Travel Planner — branded in the app as **TripMind** — is a web application that turns a destination and a few preferences into a day-by-day travel itinerary, generated by AI and drawn on an interactive map.

The goal is to combine an intuitive user experience, modern interface design, interactive maps, and AI-powered recommendations into a seamless travel planning experience.

## 🌍 Overview

Planning a trip often involves researching destinations, comparing activities, organizing schedules, and managing travel preferences across multiple platforms.

TripMind simplifies this into a single flow:

1. **Pick a destination** — search for a city, state, or country, or click anywhere on the map.
2. **Set your preferences** — trip length, interests, pace, and free-text notes.
3. **Get your itinerary** — Google Gemini plans each day, every stop is located on the map, and the walking route between stops is drawn street by street.

This project is being developed as a portfolio project, with a strong emphasis on Front-end Engineering, UI/UX Design, accessibility, and interactive web experiences.

## ✨ Features

### ✅ Implemented

#### 🏠 Landing Page
- Hero section with a trip prompt card over a full-screen map background.
- "How it works" panel and an example itinerary (Lisbon) with day tabs.
- Glassmorphism UI on top of the map.

#### 🧭 Destination Picker (`/planejar`)
- Search-as-you-type for cities, states, and countries.
- Click anywhere on the map to identify the nearest city and set it as the destination.
- Optional user location (browser geolocation), shown as a dot on the map and sent to the AI as the trip's origin.

#### 🎛️ Trip Preferences
- Trip length from 1 to 14 days.
- Interests: food, culture & museums, history, nature, nightlife, shopping.
- Pace: relaxed (2–3 stops/day), balanced (4–5 stops/day), or intense.
- Free-text notes (up to 500 characters) for anything else the traveler wants.

#### 🤖 AI-Generated Itineraries
- Itineraries generated by **Google Gemini** with structured JSON output.
- Responses validated with **Zod**; malformed answers are retried automatically.
- Fallback to a lighter model when the main one is overloaded or times out.
- Friendly error messages for quota limits, overload, and timeouts.
- "Generate again" to get a new version with the same choices.

#### 🗺️ Interactive Map
- **MapLibre GL** map with free **OpenFreeMap** tiles, recolored with a Google Maps–like palette.
- Category-colored pins for each stop (attraction, food, café, lodging, transport).
- Camera flies to the destination and fits the selected day's stops.
- Real **walking routes** between stops, with time and distance for each leg (Valhalla).
- Places the AI suggested but that could not be found on the map are listed separately.

#### 🔒 Server-Side Protections
- API keys stay on the server — all external calls go through Next.js route handlers.
- Per-IP rate limiting on itinerary generation and routing.
- Input validation on every API route.
- Routing requests are queued (≤ 1 request/second, as the public Valhalla server requires) and cached in memory.

### 🧩 Planned
- Edit, remove, and reorder activities.
- Refine an itinerary based on user feedback.
- Save trips and bookmark places (requires accounts and a database).
- Fully working map controls (layers, zoom, locate) on the landing page.

## 🏗️ Architecture

```text
app/
├── (marketing)/page.tsx        Landing page
├── (app)/
│   ├── layout.tsx              Planner layout: map + header + PlannerProvider
│   └── planejar/page.tsx       Trip planning screen
│
├── api/                        Route handlers (server only)
│   ├── geocode/search          GET  — search cities, states, and countries (Photon)
│   ├── geocode/reverse         GET  — map point → city (Photon)
│   ├── trips/generate          POST — preferences → Gemini → Photon → Trip
│   └── route                   POST — walking route between stops (Valhalla)
│
├── components/
│   ├── landing/                Hero, NavBar, PromptCard, HowItWorks, Example panels
│   ├── map/                    TripMap, pins, route line, camera, user location
│   ├── planner/                Planner panel, destination search, preferences, trip view
│   └── ui/                     Button, GlassPanel, Panel, Logo
│
└── lib/
    ├── ai/                     Gemini client, prompt, Zod schema
    ├── geo/                    Geocoding, routing, map style, bounds, user location
    ├── trip/                   Types, preferences, validation, trip builder, sample trip
    └── rate-limit.ts           In-memory per-IP rate limiting

scripts/copy-maplibre-worker.mjs   Copies the MapLibre worker to public/ (postinstall)
```

### Itinerary generation flow

```text
Browser ──POST /api/trips/generate──▶ rate limit ▶ validate request
                                            │
                                            ▼
                               Gemini (structured JSON, Zod-checked)
                               returns days + place names per stop
                                            │
                                            ▼
                         Photon finds the coordinates of each stop
                         (searched within ~110 km of the destination)
                                            │
                                            ▼
                     Trip { days, activities, coordinates, notFound }
                                            │
Browser ◀───────────────────────────────────┘
   │
   └──POST /api/route (per day)──▶ Valhalla ──▶ walking path + time/distance per leg
```

## 🚀 Getting Started

### Prerequisites
- Node.js 20+
- A free Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)

### Setup

```bash
git clone https://github.com/CaioScura/AI-travel-planner.git
cd AI-travel-planner
npm install          # also copies the MapLibre worker into public/
cp .env.example .env.local
```

Fill in `.env.local`:

| Variable | Required | Description |
|---|---|---|
| `GEMINI_API_KEY` | Yes | Gemini API key |
| `GEMINI_MODEL` | No | Main model (default: `gemini-3.8-flash`) |
| `GEMINI_FALLBACK_MODEL` | No | Lighter model used when the main one is overloaded (default: `gemini-3.5-flash-lite`) |
| `ROUTING_URL` | No | Valhalla server (default: `https://valhalla1.openstreetmap.de`) |
| `GEOCODER_URL` | No | Photon server (default: `https://photon.komoot.io`) |

> ⚠️ Never commit `.env.local` — it is listed in `.gitignore`.

### Scripts

| Command | Description |
|---|---|
| `npm run dev` | Start the development server at http://localhost:3000 |
| `npm run build` | Production build |
| `npm run start` | Run the production build |
| `npm run lint` | Run ESLint |

## 🔒 Security and Reliability

Already in place:

- API keys and secrets stay on the server (`.env.local`, route handlers only).
- Every API route validates its input (coordinates, trip length, interests, notes length).
- AI output is validated with Zod before it is used.
- Per-IP rate limiting on the AI and routing endpoints.
- Timeouts, retries, and a fallback model for the AI provider.
- Respect for public OpenStreetMap services: identifying `User-Agent`, request queue, and caching.

Planned:

- Authentication, authorization, and protection of user-specific travel data.
- Persistent rate limiting (the current one lives in server memory).
